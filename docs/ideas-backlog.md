## Те, що вичавлює вже зібрані дані

### A. Цінова аналітика — «де дешевше» + інфляція кошика

Таблиця `product_prices` (append-only знімки `price_orig` + `price_net` по товару ×
магазину × даті) наповнюється auto-link при кожному збереженні чека, але в UI її
**не видно ніде**. Що можна зробити:

- **Де дешевше** — для товару ціна по магазинах: «Хліб: ATB 0.89 · Сільпо 1.10».
- **Тренд ціни товару** — «Молоко: 1.39 → 1.59 за 3 міс (+14%)».
- **Персональний індекс інфляції** — як подорожчав саме _ваш_ реальний кошик.

Жоден типовий фінтрекер цього не має — ні в кого немає ваших чеків по позиціях.
Потрібно: 1–2 view + сторінка `/prices` (або вкладка товару). Нульовий новий збір даних.

### C. Розумні підказки на екрані перевірки чека

Під час review показувати аномалії з історії: «Milka на 0.40 дорожча, ніж минулого
разу», «цей чек удвічі більший за звичайний у цьому магазині». Перетворює пасивний
облік на активну економію. Джерело — той самий `product_prices` + by-store середні.

## Те, що прибирає тертя

### B. Telegram-бот для завантаження чеків

Зараз: відкрити застосунок → /photo → вибрати фото → чекати. Тертя вбиває звичку.
Замість цього — переслав фото боту, і чек уже в `/pending` або збережений. Бот кличе
ту саму `parse-receipt` Edge Function. Для пари, що фоткає чеки на ходу, це різниця
між «ведемо» і «закинули».

## Операційна гігієна (відкладено з Phase 12)

- **Бекап БД** — daily dump → Storage `backups/` через pg_cron + Edge Function. Для
  фінансових даних ризик №1: зараз бекапу немає.
- **Orphan-фото sweep** — періодичне прибирання фото-сиріт у Storage (мережа впала
  між upload і save). Відкладено у `use-save-photo-receipt-mutation.ts`.
- **Атомарність save/update** — перенести вставку у Postgres RPC, щоб failure після
  DELETE items не лишав видимий порожній чек.
- **Показ фото на /edit** — `photo_url` зберігається, але оригінал чека ніде не
  рендериться; не можна звірити OCR із джерелом.
- **Loading skeletons** замість text-only «Завантажую…» на /recent і /stats.
- **E2E (Playwright, Phase 11)** — два потоки (photo-save + manual-save).
